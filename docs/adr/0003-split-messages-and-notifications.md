# ADR-0003：消息与通知拆成两个页面

**状态**：已采纳（2026-09）

## 背景

一个页面同时承载「私信/群聊」和「通知（评论与 @、赞和收藏、新增关注）」时，
左栏要放两套语义完全不同的列表：一边是**可回复的会话**，一边是**只读的事件流**。
实际使用中两者行为差异很大：

| 维度     | 消息（私信/群聊）              | 通知                                         |
| -------- | ------------------------------ | -------------------------------------------- |
| 左栏对象 | 会话（人/群）                  | 事件类型分类（评论与 @、赞和收藏、新增关注） |
| 右侧内容 | 聊天记录 + 输入框 + 群设置     | 事件列表，无输入                             |
| 状态     | 未读、置顶、免打扰、归档、草稿 | 已读/未读                                    |
| 手势     | 左滑删除、右滑置顶、长按更多   | 无                                           |

混在一起会让「输入框只属于消息」这类约束靠条件渲染硬撑，状态也互相干扰。

## 决定

- `MessagesPage`：只管私信与群聊（`PageName = 'messages'`）
- `NotificationPage`：只管通知，内部分三类（`PageName = 'notifications'`）
- 两者共用 `AppShell` 外壳与设计 token，但**不共用列表组件**

## 后果

- ✅ 各自的交互（群管理、未读分隔线、事件分类）能各自演进
- ✅ 两页可独立懒加载，首屏更小
- ⚠️ 左栏两种列表长得像但实现不同，改样式时**两处都要改**（这是刻意接受的重复，好过耦合）
