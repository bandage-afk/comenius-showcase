# ADR-0007：教师模块范围收敛，「我的」合并成一个页面

**状态**：已采纳（2026-09）

## 背景

教师模块（`src/teacher/`，来自领英那份 Figma zip）自带一整套社交产品：Home / My Network /
Jobs / Messaging / Notifications / Me。其中：

- **Messaging 与 Notifications 和主站完全重复**，而且是简化版：主站消息页有群聊、公告、管理员、
  引用、撤回、语音、笔记卡、左滑删右滑置顶；tutor 那版只有一个单聊列表 + 输入框，而且它的
  Enter 发送**没有判断中文输入法**，选词时按回车会误发。
- **Jobs 没有任何真实数据来源**（纯 mock 招聘帖），也不是这个产品的业务方向。
- **Me 是第二份「我的」**：主站有自己的「我的」（笔记 / 收藏 / 点赞 / 学习档案 / 贴纸），
  tutor 又有一个（经历 / 学历 / 技能 / 证书 / 简历）。同一个人有两套资料界面，
  而且 tutor 那份是**组件内 `useState`，刷新就丢**。

## 决定

1. **教师模块只保留「动态（Home）」与「人脉（My Network）」**，删除 Jobs；顶栏 Me 下拉里的
   View Profile 指向主站「我的」。
2. **私信与通知统一走主站的「消息 / 通知」页**。tutor 的通知里有三样主站缺的东西——
   已读状态、全部标为已读、按分类的通知设置——这三样**移植到主站通知页**，
   但**版式不动**：设置做成右上角齿轮弹层，而不是 tutor 那种常驻右栏。
3. **「我的」合并成一个页面**（`profile` 路由），顶部「社区 / 职业」双视图：
   - 社区面：笔记 / 收藏 / 点赞 / 学习档案 / 贴纸（原有）
   - 职业面：经历 / 学历 / 技能 / 证书 / 语言 / 志愿 / 项目 + 简历预览（来自 tutor）
   - **身份只有一份**：姓名、头像、封面、简介、地区、生日…都存在 `profileStore`，
     两个视图读同一份、改同一份（字段名统一用社区那一套：`avatarUrl` / `bg` / `bio` / `region`）
   - 职业档案的条目也进 `profileStore` 并**持久化**（带 version + migrate）
   - 从教师模块进「我的」时带 `navigate('profile', 'career')`，直达职业视图

## 后果

- ✅ `TeacherApp.tsx` 从 **3268 行降到约 700 行**；职业档案搬到 `src/profile/`
  （`career.ts` 放类型与默认值、`CareerProfile.tsx` 放视图与编辑弹窗），
  领英版式的 UI 原子抽到 `src/teacher/ui.tsx` 供两边共用
- ✅ 教师档案的编辑**刷新后不再丢**（以前只在内存里）；主站「我的」的资料顺带也持久化了
- ✅ 通知有了已读状态，左栏「通知」也挂上了未读角标
- ⚠️ 切「社区 / 职业」是整块替换内容，两个视图各自维护自己的头部样式；
  以后新增身份字段要同时想清楚它在两个视图里怎么显示
- ⚠️ 默认数据仍是 mock：`headline` 默认是「A-Level 数学 / STEP 教师 · 国际课程备考」，
  经历等用的是教师视角的示例内容。真实身份要让用户自己改（或接后端），
  不要在代码里写死成"某个人"
- ℹ️ 模板里还留着「Try Premium」这类领英原生元素，属于版式装饰，暂无功能
